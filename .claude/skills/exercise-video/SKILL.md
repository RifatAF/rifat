# exercise-video

Человек в кадре выполняет упражнение технически верно, ролик проходит автопроверку позы и только после одобрения человеком попадает в приложение. По умолчанию всё бесплатно.

## Запуск одной командой

```bash
python3 .claude/skills/exercise-video/scripts/ev.py run <id>
```

Первый раз в окружении: `python3 .claude/skills/exercise-video/scripts/ev.py setup` (создаст `.venv` скилла, поставит зависимости, скачает модель позы; дальше `ev.py` сам запускается в этой `.venv`). На Linux для MediaPipe нужны `libegl1 libgles2`.

Остальные команды: `validate`, `status`, `approve`, `reject`, `reset-attempts`, `reference`, `publish`, `selftest` (`ev.py -h`).

## Где что лежит

| Путь | Что |
|---|---|
| `exercises/<id>.json` | единственный источник правды по упражнению, схема `exercises/_schema.json` |
| `config.json` | провайдер, стиль библиотеки (человек, одежда, пол, свет, камера), лимиты, допуски QA |
| `templates/` | промты (эталон, ключевой кадр, клип, негатив), тексты карточек, запрещенные фразы, шрифт Onest |
| `scripts/ev.py`, `scripts/evlib/` | конвейер: генерация, ffmpeg, MediaPipe QA, manifest |
| `scripts/evlib/providers/` | один адаптер на провайдера |
| `library/<провайдер>/reference.png` | эталон человека, одежды и фона для всей библиотеки (коммитится) |
| `manifest.json` | статус каждого видео: draft, qa_passed, approved, rejected (коммитится) |
| `reports/<id>_v<n>.qa.md/.json` | отчеты автопроверки (коммитятся) |
| `out/<id>_v<n>.mp4/.jpg` | черновики, `work/` кэш кадров и клипов (не в git) |
| `video/` в корне репозитория | только одобренные ролики, кладет `publish` |

## Процесс

1. **Данные.** `ev.py validate <id>`. Если ошибки (нет углов, фаз, стороны, ракурса, подсказок): спроси у человека только недостающее, одним списком. Не придумывай углы и противопоказания: это решает специалист.
2. **Эталон библиотеки.** При первом запуске создается `library/<провайдер>/reference.png` (стоя, левым боком к камере, стиль из `config.json`), проходит проверку позы и фиксируется хэшем. Покажи его человеку. Все кадры всех упражнений делаются редактированием этого эталона. Подмена файла останавливает конвейер (код 11), пересоздание только по просьбе: `ev.py reference --reset`.
3. **Ключевые кадры.** Стартовая поза и конец каждой фазы движения: редактирование эталона, сразу проверка углов MediaPipe (±10°). Кривая поза ловится на картинке, до генерации видео.
4. **Клипы.** Image-to-video, один клип на фазу движения, от ключевого кадра к ключевому кадру (первый и последний кадр заданы, поэтому повторы склеиваются без скачков). Паузы делаются стоп-кадром, а не генерацией.
5. **Ценовой шлюз.** После первого клипа конвейер останавливается (код 3). Покажи человеку клип, потраченное и оценку остатка (для бесплатных провайдеров: расход дневной квоты). После ОК: `ev.py run <id> --confirm-cost`.
6. **Сборка.** Обрезка неподвижных краев, подгонка каждой фазы ровно под темп из JSON, повторы, замедленный повтор ключевой фазы с типичными ошибками, вступление и концовка, русские титры, метка «Видео создано ИИ» весь ролик. 1080x1920, 30 fps, H.264, не больше 8 МБ.
7. **Автопроверка.** MediaPipe по каждому кадру: углы на старте и в конце каждой фазы каждого повтора (±10°), число повторов, длительность цикла и фазы, анатомия (стабильность длин костей, скачки точек), один человек в кадре, сторона к камере, ограничения из JSON, технические параметры файла. Отчет в `reports/`.
8. **Статус.** Все проверки пройдены: `qa_passed`. Нет: остается `draft`, плохие фазы помечаются, следующий `run` перегенерирует только их.
9. **Человек.** Покажи ролик, превью и отчет. Статусы `approved` и `rejected` ставит только человек: `ev.py approve <id> --version N --by ИМЯ` в своем терминале. Если он одобрил в чате, передай его слова дословно: `--human-said "..."`. Сам не одобряй никогда.
10. **Публикация.** `ev.py publish`: копирует только `approved` в `video/` и пишет в `data/exercises.json` у `app_id` поля `media.video`, `media.poster`, `media.aiGenerated`, `media.aiLabel`. Файл, измененный после одобрения, не публикуется.

## Пилот и масштабирование

Сначала одно упражнение целиком. Спроси у человека, какое (список: `data/exercises.json`), составь `exercises/<id>.json` вместе с ним, прогони до `qa_passed`, покажи отчет автопроверки и ролик. Остальные упражнения только после его ОК. Правые версии делай зеркалом левых (`"mirror_of"`), без генерации.

## Правила

- **Бесплатно по умолчанию.** `config.json → allow_paid: false`. Платный провайдер (fal) не запустится (код 13), пока человек сам не включит. Без его прямой просьбы `allow_paid` не меняй.
- **Лимиты сторонних сервисов.** У бесплатных Spaces дневная квота ZeroGPU (без `HF_TOKEN` маленькая), у коннекторов свои кредиты. Скилл держит свой дневной предохранитель (`daily_limits`) и останавливается до вызова (код 14). Квота кончилась: сообщи и продолжи на следующий день той же командой, готовое возьмется из кэша. Не обходи лимиты сменой аккаунтов или IP.
- **Попытки.** Не больше 3 неудачных попыток на упражнение (`max_attempts_per_exercise`), дальше код 4: остановись и спроси человека, что поправить (JSON, промт, ракурс). Обнуляет только человек: `reset-attempts`.
- **Идемпотентность.** `qa_passed` и `approved` не перегенерируются. Новая версия только по просьбе: `--new-version`. Кэш кадров и клипов по хэшу промта и входов.
- **Ключи** только из переменных окружения (`HF_TOKEN`, `FAL_KEY`), не в файлы и не в чат.
- **Тексты.** Только техника. Никаких «вылечит», «уберет боль», «избавит от грыжи»: `templates/banned_phrases.txt` проверяется при валидации и перед сборкой.
- **Метка ИИ** на всем ролике и в карточке (`media.aiLabel`). Не убирать.
- **Единый стиль.** Человек, одежда, пол, свет, камера, фон одинаковы для всей библиотеки (`library_style`). Менять только до первого эталона.

## Подводные камни и как они закрыты

| Камень | Защита |
|---|---|
| Лишние или вывернутые конечности, колено внутрь, прогиб поясницы | QA углов и длин костей по каждому кадру, ограничения `constraints` в JSON, проверка ключевых кадров до видео, негативный промт. Пальцы и лицо автопроверка не видит: смотрит человек |
| Лицо и одежда «плывут» | один эталон на всю библиотеку, все кадры из него, клипы между двумя заданными кадрами, фиксированный seed где поддерживается |
| Быстрое или зацикленное движение | одна фаза на клип, в промте «одно движение, без повторов», темп задается при сборке, QA считает повторы и длительность |
| Путаница левого и правого | стороны анатомические; в промте явно: «LEFT side faces the camera, faces the LEFT edge of the frame» (человек лицом к левому краю кадра повернут к камере левым боком); QA сверяет видимость сторон; зеркальные версии меняют все `_left`/`_right` и требуют свои тексты, если в исходных есть «левый/правый» |
| Разный пол, свет, фон | `library_style` в каждом промте и редактирование одного эталона |
| Медицинские обещания | список запрещенных фраз |
| Стоимость | бесплатные провайдеры, шлюз после тестового клипа, бюджет `budget_usd_per_exercise`, журнал расходов в manifest |

## Провайдеры (`config.json → provider`, или `--provider`)

| Провайдер | Цена | Как работает |
|---|---|---|
| `hf_spaces` (по умолчанию) | бесплатно, квота ZeroGPU | FLUX.1-schnell (эталон), FLUX.1-Kontext (позы), Wan 2.2 first-last-frame (клипы). Space и параметры в config: если Space сломался, замени его там же, сверив `https://<space>.hf.space/gradio_api/info` |
| `inbox` | бесплатно в пределах тарифа коннектора | конвейер пишет заявку `work/<id>/inbox/*.request.json` и останавливается (код 9). Ты генерируешь файл доступным коннектором (например ElevenLabs, Adobe Firefly), сохраняешь по указанному пути и запускаешь снова. Перед генерацией проверь остаток бесплатных кредитов и скажи человеку, сколько уйдет; платные кредиты без его согласия не трать |
| `mock` | бесплатно, офлайн | рисует манекен по углам из JSON. Для тестов конвейера, не для публикации |
| `fal` | платно | Kling 2.6 Pro и nano-banana. Только при `allow_paid: true` и `FAL_KEY` |

Новый провайдер: файл `scripts/evlib/providers/<name>.py` с классом `Provider(Base)` (методы `generate_image`, `edit_image`, `image_to_video`), строка в `REGISTRY`, секция в `config.json`.

## Коды выхода и что делать

| Код | Значит | Действие |
|---|---|---|
| 0 | готово (или уже qa_passed) | покажи ролик и отчет, жди решения человека |
| 1 | автопроверка не пройдена | покажи отчет; если попытки есть, запусти снова (перегенерируются плохие фазы) |
| 2 | ошибка данных | спроси человека недостающее |
| 3 | тестовый клип готов или превышен бюджет | покажи клип и цену, жди ОК |
| 4 | лимит попыток | остановись, обсуди с человеком |
| 9 | ждем файл в inbox | сгенерируй коннектором по заявке |
| 10 | кадр не прошел проверку позы | запусти снова (перегенерируется только он); повторяется: правь `end_pose_en` |
| 13 | платный провайдер запрещен | используй бесплатный |
| 14 | квота исчерпана | сообщи, продолжи позже |
| 5, 6, 7, 8, 11, 12, 15 | окружение, ключ, провайдер, ffmpeg, эталон, зеркало, нужен человек | текст ошибки говорит, что делать |

## Как писать exercises/<id>.json

Пример: `exercises/test_squat.json` (тестовое, `test_only`). Главное:
- `camera.view`: `side` для сгибаний и разгибаний (углы меряются в плоскости кадра), `front` для наклонов и поворотов. `facing_side`: какая сторона тела к камере; метрики бери на этой стороне.
- `start_pose.targets` и `targets` фаз: метрики `knee_*`, `hip_*`, `ankle_*`, `elbow_*`, `shoulder_*`, `neck_flexion_*`, `trunk_incline`, `trunk_lateral`, `head_yaw`, `pelvis_tilt` (`*` = `left`/`right`, сторона человека).
- Фазы: первая `move`, последняя `move` с `returns_to_start: true`, паузы `hold` между ними. `duration_s` задает темп, строка темпа для титров строится сама.
- `primary_joint`: метрика с амплитудой не меньше 15° в `key_phase`, по ней считаются повторы.
- `cues_ru` ровно 3, `mistakes_ru` ровно 2, до 64 знаков, без медицинских обещаний. `contraindications_ru` обязательно.
- Лежачие упражнения (мостик, «ракушка»): только боковой ракурс, MediaPipe на них точнее всего сбоку.
- Правая версия: `{"id": "..._right", "mirror_of": "..._left", "app_id": "..._right", "title_ru": "... (правая сторона)"}` и свои `cues_ru`, если в левых есть слова о стороне.

## Проверка самого скилла

`ev.py selftest`: во временной папке через `mock` проверяет валидацию, ценовой шлюз, поимку зацикленного движения, перегенерацию только плохой фазы, идемпотентность, запрет одобрения без человека и запрет платного провайдера. Боевой manifest не трогает.
